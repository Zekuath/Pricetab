# PriceTab for iPhone

The same PriceTab that runs on every new tab, as an app on an iPhone (built
and laid out for the Pro Max, runs on any iPhone on iOS 17 or later), with:

- **its own memory** — every setting, coin, target, call, the portfolio and
  the practice account are kept in the app's web storage, which survives
  relaunches and updates (the app has a real origin, `pricetab://app`, so
  storage is keyed to it and never to a temporary file path);
- **a home-screen widget** — your coins' prices in the app's own order and
  currency, live from the same public endpoint the app polls, in small,
  medium and Lock Screen sizes; long-press → Edit to pin one coin;
- **everything the extension has** — the chart, targets, calls, the
  portfolio, the derivatives page with its assistant, the news panel, the
  in-app widget cards and their settings (Settings → Widgets), all twelve
  languages.

- **its own bar** — a Liquid Glass bar (iOS 26 and later; a thin material
  before that) floating at the foot with Chart, Targets, Calls, Portfolio,
  Futures and Settings, each pressing the page's own keyboard shortcut, so
  every panel is one thumb away without the corner buttons;
- **both orientations** — portrait and landscape; on a phone on its side the
  widget dock stands down so the chart and the calls board have the height.

- **the alarm, both halves** — the page's *Notification* switch asks iOS
  for notification permission (straight out of the press, like the
  extension asks Chrome) and a hit target or a stopped-out contract then
  raises an iOS banner with a sound, in front of the app or not; *Give it
  back* stops the app posting. The *Sound* switch plays the same two-tone
  alarm as the extension — iOS keeps a page silent until it has been
  touched once, so the shim unlocks the audio on the first touch and hands
  the page that one context.

What it does not have, honestly: the six newsrooms behind an optional Chrome
host permission — no such thing on iOS, so the news panel says so in one
line instead of offering a button that would only ever be refused. The five
open sources work.

## Layout

```
ios/
├── project.yml            # the Xcode project, generated by XcodeGen
├── PriceTab/              # the app: SwiftUI shell, WKWebView, bridge
├── PriceTabWidget/        # the WidgetKit extension
├── Shared/                # the App Group store both targets read
├── webshim/ios.js         # loaded before the app's scripts on the phone
├── scripts/build-webapp.sh# copies ../src, ../vendor, ../_locales here
└── WebApp/                # generated — the page the app serves (ignored)
```

Nothing in the extension is changed; the phone app reads the same `src/`.

## Build and install on your own iPhone

1. **Tools.** Xcode 16 or later (this was built with Xcode 27 / iOS 27 SDK)
   and XcodeGen: `brew install xcodegen`.
2. **The page.** From this folder: `./scripts/build-webapp.sh` — copies the
   web app into `WebApp/`, adds the shim to `index.html`, builds the icon.
   Run it again after any change under `src/`.
3. **The project.** `xcodegen generate` → `PriceTab.xcodeproj`. Open it.
4. **Signing.** Select the `PriceTab` target → *Signing & Capabilities* →
   *Team*: your Apple ID (a free personal team works; add it under Xcode →
   Settings → Accounts). Do the same for `PriceTabWidget`. If Xcode asks
   to register the App Group `group.com.pricetab.app`, let it. With a
   personal team the bundle id must be unique to you: change
   `com.pricetab.app` and `com.pricetab.app.widget` in `project.yml` (keep
   the `.widget` suffix), re-run `xcodegen generate`.
5. **The phone.** Plug it in, unlock it, trust the Mac. On the phone:
   Settings → Privacy & Security → *Developer Mode* → on (it restarts).
   In Xcode pick your iPhone as the run destination and press **Run**.
6. **First launch.** iOS will refuse an app from an unknown developer once:
   Settings → General → VPN & Device Management → your Apple ID → *Trust*.
   Launch again.
7. **The widget.** Long-press the Home Screen → **+** → search *PriceTab* →
   pick a size → *Add Widget*. Open the app once so it has sent the widget
   your coin list; the widget then refreshes on its own every 15 minutes.
   Long-press the widget → *Edit Widget* to pin one coin.

A free personal team signs the app for **7 days**; after that it stops
opening until you press Run again. A paid Apple Developer account signs it
for a year and can put it on TestFlight.

## QA — what was checked, and how to check it again

Two scripts walk the page the way a thumb would, in Playwright's WebKit
(the engine inside WKWebView) at the Pro Max size, with every network
answer stubbed. They need the bundle built (`./scripts/build-webapp.sh`)
and the test dependencies installed (`npm --prefix ../tests ci`, plus
`npx --prefix ../tests playwright install webkit` once):

```
node ios/scripts/qa-phone.js portrait     # 159 checks, ~2 min
node ios/scripts/qa-phone.js landscape    # the same walk on its side
node ios/scripts/qa-shim.js               # the bridge, with a fake native side
```

`qa-phone.js` presses every screen and control by touch — the range
switcher, Settings (three tabs, a widget switch there and back), Targets
(add one, see it, remove it), Calls (on, the board on the chart, off),
Portfolio (a holding in its field), the derivatives page (every desk tab,
a contract opened from the ticket, every reading tab, Close all pressed
twice), News, the quick switch, base rates, the alarm row — and after every
step asserts four things: no page error; no horizontal overflow; every
visible control is its own hit target (a control another element covers is
retested after scrolling it into view, so a sticky foot over a row is fine
and a button under a chart is not); and a press 12px off the centre of any
control under 24px still lands on a control, never on dead space.
Screenshots of every screen land in `build/qa/`.

`qa-shim.js` fakes `webkit.messageHandlers.pricetab` and checks the round
trips: the alarm's Notification switch asks the app (`notifyRequest`), the
app's yes turns it on and shows *Give it back*, which sends `notifyOff`;
the Sound switch plays through the one unlocked `AudioContext`;
`chrome.notifications.create` reaches the app with its words; a host
permission (the newsrooms) is refused rather than faked.

The pass on 21 Sep 2026 found, and the fixes went into the extension's own
styles because they are narrow-window bugs there too:

| Found | Fixed |
|---|---|
| On a phone the Calls and Derivatives corner buttons sat on the same spot (the phone-width rule restated the offsets by hand and had not learned about the fifth button) | the phone rule reads the same slot the desktop one does |
| Targets on a phone on its side: the list was a 30px slot under a full-height form, the one target in it unreachable | below 520px of height the card scrolls as one surface |
| News on a phone on its side: the panel's × drawn exactly under the page's corner × | the panel's × stands down where the two meet |
| The ticket's sticky foot and a bottom ticker sat under the app's bar | both add the bar's lift |
| Eleven controls under 20px — the widget cards' ×, coin chips' ×, the "?" rings, the news and base-rate ×, text-link buttons | an invisible 36px touch box on every one of them, only under `pointer: coarse` |
| Settings switches said nothing about which way they were | `aria-pressed` on all 22 |
| The news panel offered *Turn on full sources*, a Chrome permission iOS cannot grant | one honest line on the phone |

Not checked by a script: the widget gallery, the notification permission
sheet and a banner on a locked phone — each needs a hand on a real device.

## Simulator

`xcodebuild -project PriceTab.xcodeproj -scheme PriceTab -destination
'platform=iOS Simulator,name=iPhone 17 Pro Max' build`, then
`xcrun simctl boot "iPhone 17 Pro Max"`, `xcrun simctl install booted
<path to PriceTab.app>`, `xcrun simctl launch booted com.pricetab.app`.
The page's console is in Safari → Develop → Simulator → PriceTab.

## How it works

- `WebView.swift` makes a `WKWebView` with the default (persistent) website
  data store and registers `AppSchemeHandler` for `pricetab://app/…`, which
  serves files from the bundled `WebApp/` folder with their media types.
  Links out (a headline) open in Safari; the page never navigates away.
- `GlassBar.swift` floats over the page and presses the page's shortcuts
  through `window.PriceTabIOS.press(key)`, which the shim defines; the shim
  also sets `--pt-dock-lift` so the page's widget dock rises above the bar.
- `webshim/ios.js` pads the page for the safe areas and, every minute and
  on load, reads the coin list, currency and ticker cache the page already
  keeps in localStorage and posts them to `Bridge.swift`, which writes a
  `WidgetSnapshot` into the App Group and reloads the widget timelines. It
  also defines the `chrome` the page asks for notifications through —
  `permissions.contains/request/remove` for `notifications` become round
  trips to `Notifier.swift` (a request carries an id; the app answers with
  `PriceTabIOS.resolve(id, granted)`), `notifications.create` posts a
  banner, and any *host* permission is answered false — and it unlocks one
  `AudioContext` on the first touch, handing the page that context whenever
  it asks for one, so the alarm's tone is not the one iOS swallows.
- `Notifier.swift` is `UNUserNotificationCenter`: asks straight out of the
  switch's press, shows a banner with sound even while the app is in front
  (the page's toast says it too, but a banner is what somebody in another
  app gets), and keeps a *muted* flag for *Give it back*, since iOS has no
  way to hand a permission back the way Chrome's optional ones can.
- `PriceTabWidget.swift` reads that snapshot, fetches the shown coins'
  spot prices from Coinbase (8 s timeout each, in parallel), and asks to be
  refreshed after 15 minutes. The 24 h change comes from the app's last
  visit — the widget says when it was last drawn, never pretends the change
  is live.
- No analytics, no account, no server: the same promise as the extension.
